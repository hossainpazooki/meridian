## Locked decisions

Do not relitigate; pick-up may check whether each reason still holds.

1. **`canon.Marshal` refuses non-ASCII** rather than reimplementing Python's
   `ensure_ascii` escaping in Go. Reason: the spec already restricts every
   string in the system to ASCII, so the escaper would serve a domain the spec
   excludes, and surrogate-pair escaping in the most load-bearing primitive is
   latent risk for no in-scope benefit. Fail-closed is this project's idiom.
   OPEN if MERIDIAN should ever carry non-ASCII text (instrument names,
   counterparties) -- then the escaper is the right answer and this flips.

2. **The expected-view schema uses `feed_seq`, not `seq`.** The plan specified
   `seq`; that key never appears in a snapshot document, so every diff scored
   it ABSENT on every comparison including the LIVE cells, and P1's and P3's
   live cells could never have gone GREEN. The other branch was foreclosed:
   `feed_seq` is hardcoded in the already-built snapshot/asof/reconcile layers.
   Bonus, not designed for: `feed_seq` is now compared BY VALUE, so a document
   folded to the wrong viewpoint fails loudly.

3. **No cap on unparseable lines in `feed.Open`.** A bound of one was tried and
   is a false refusal that permanently bricks a ledger after two ordinary
   crashes (each recovery write's leading newline terminates the previous
   residue), with no repair path since bytes are never rewritten. Record
   integrity does not rest on a cap: the seq and prev legs refuse any deleted,
   altered, or reordered record. Residue is COUNTED and exposed instead.

4. **Two denominator helpers, not one.** `SetEquality` uses `len(got union
   want)`; `SetEqualityOverUniverse` uses the caller-supplied universe. A
   helper cannot know its caller's meaningful scope, and baking a guess in
   produces a denominator that looks principled and means nothing.

5. **P6's `golden.json` is the sole source of truth for P6** -- no
   generator-published P6-scoped `positions_at`/`unevaluable_at`. It is
   deliberately HAND-COMPUTED to escape cross-implementation agreement; a
   generator-published list would be a second, lower-authority source.
   Accepted cost: any future change to P6's traded instruments needs the same
   hand-verification discipline.

6. **CI pins Python 3.14**, the interpreter that produced the fixtures, with
   the reason stated in the workflow rather than floating. Pinning to a version
   nobody has verified would make CI check a claim we have not made.

7. **`positions_match_golden` earned its own twin.** It read 0 in every cell
   and so was an uncredited check about to be counted as evidence. The phantom
   twin (`invented_untraded_position`) proves it is the ONLY thing in the build
   that catches an invented position -- `leaf_diff` walks the golden's keys
   only and is structurally blind to `ZZZ`.

## Invariants

- **The twin rule.** A property is CLAIMABLE only when its live cell is GREEN
  and EVERY twin is RED with `checks` exactly equal to
  `planted.expected_violations`. P4 has two twins, P6 three. A gate that has
  never run red proves nothing. Violating this makes STATUS.md, BASELINE
  registration and the CV dishonest at once.
- **STATUS.md is the state of record; README never carries counts.**
- **A manifest/gate expectation change is RED in one direction while it
  lands.** Manifest-first leaves a planted expectation with no computed check;
  gate-first leaves a check with no expectation. Emit refuses both. This is
  correct behaviour, not a defect -- a harness tolerating the mismatch is
  exactly the hole that let eight zero-valued expectations go unenforced.
- **A guard nobody has watched fire is not known to work.** Every generator
  guard has a negative control; the freshness harness proves fixtures match the
  generator, NOT that plants are strong -- whoever weakens a plant regenerates
  and both go green together.
- **Contention hazard:** all agents in a session share one checkout, so
  `MERIDIAN_VERDICT_DIR` resolves to the same `gates/out`. Concurrent
  `go test` runs double every row. This was hit again while writing this brief
  (30 rows, every property `NO (duplicate rows)`) and the runner named the
  cause instead of reporting a false regression. **Check the row count before
  believing a low claimable count.**
- No wallclock in the fold; no floats anywhere; the feed is the only input;
  the naive fold stays import-pinned; no performance vocabulary anywhere.
- **CV/site silence until all six properties hold both cells** -- they now do,
  but see the honest limits in STATUS.md before writing a word publicly, and
  note that nothing is committed or CI-verified yet.
