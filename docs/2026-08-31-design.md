## 1. Core: feed, fold, time, money

**One feed, one fold, everything else derived.** Go module `meridian`. The only
durable *input* is a single append-only feed on disk: JSONL, one event per line,
fsync on append, hash-chained (each record carries the previous record's hash) —
the intent-plane feed transplant. Positions, basis, P&L, refusals, snapshots are
all fold output, recomputable from the feed alone.

**Reference data rides the feed.** Prices and action terms are feed events, not a
side table. P4 becomes PIT-native for free: "missing reference data" means *no
price event in the visible prefix*, and a price learned after viewpoint V is
invisible at V by construction.

**Event types (v1, closed set):** `fill` (buy/sell), `price`, `action`
(split | cash dividend; carries effective, announced, processed dates),
`action_amendment` (references an action id, corrected terms).

**Two timelines, one clock.** Feed sequence number = knowledge time — the only
clock; wallclock never enters the fold. Each event also carries its domain
effective date. An as-of read at viewpoint V folds exactly events `[0..V]`,
applying each at its effective date within the reconstructed history. The
amendment needs zero special machinery: it is just a later event; viewpoints
before its seq see the original terms.

**Fold state per instrument:** integer quantity + integer total-cost in minor
units; plus cash balance, accumulated realized P&L, and refusal records (P1
collisions, P4 unevaluables) as first-class state.

**Money: no floats, one division, one stated rule.** All amounts are integer
minor units. Average cost is never stored — state holds `(total_cost, qty)`,
both exact integers, so buys, splits (qty × ratio, cost unchanged) and dividends
(cash += qty × rate) never round. Division happens at exactly one point — cost
relieved on a sell: `relieved = round_half_even(total_cost × qty_sold / total_qty)`,
subtracted from `total_cost`. One rule, one location, deterministic — this is
what makes P2's byte-identity achievable with P6's math inside the fold.

**Snapshot:** canonical JSON (sorted keys, fixed integer encodings),
sha256-named, content-addressed, stamped with the hash of the feed prefix it
derives from. Positions + cash + basis + realized P&L + refusals in one artifact.

**P1 mechanics:** idempotency key = hash over the fill's identity fields,
derived in the ledger, never producer-supplied. Same key + same payload hash →
absorbed, zero effect. Same key + different payload hash → one durable refusal
record.

**As-of reads:** pure recompute — replay the visible prefix through the fold on
every read. No materialized derived state exists, so no restatement-of-derived-
state bug class exists. Fine at fixture scale; Lane 2 (ClickHouse) is the
serving layer later.

**CLI:** `meridian append | replay | snapshot | asof --seq N | reconcile
--statement <file>`.

## 2. Properties and twins

Each property is claimable only when its green cell passes **and** its twin cell
fails for exactly the planted reason, with exact counts.

| # | Property | Green gate | Known-bad twin |
|---|---|---|---|
| P1 | At-most-once fill ingestion | Planted duplicate absorbed with zero position effect; planted collision lands as exactly one refusal record | Counts exact — 1 absorption, 1 refusal |
| P2 | Deterministic replay | Same feed prefix folded twice (fresh process) ⇒ byte-identical snapshot, hash-verified | Mutate one event ⇒ hash diverges; reorder two events ⇒ divergence caught (feed sequence is authoritative; no commutativity claim) |
| P3 | PIT-correct corporate actions | As-of reads around each action's *processed* seq return only what was knowable; the amendment yields three distinct consistent histories | Leak corrected terms into a viewpoint that should see only original terms ⇒ no-lookahead check red on exactly the affected rows |
| P4 | Fail-closed valuation | Withhold one `price` event ⇒ exactly the dependent positions carry a durable `unevaluable` record; all else green | Withheld-row count matches planted count exactly; never a silent zero or stale carry-forward |
| P5 | Reconciliation proven able to fail | Snapshot reconciles field-by-field (quantity, cash, basis) against generator-emitted custodian statements; exact, zero tolerance | Plant one basis point of drift ⇒ gate names the instrument and the amount |
| P6 | Portfolio math correctness | Fold matches a hand-computed golden fixture (small portfolio, one split, one sell) to the cent | Perturb one price ⇒ exactly the dependent unrealized P&L moves, byte-stable elsewhere; mutate one fill ⇒ exact divergence caught |

## 3. Fixtures and the naive fold

`fixtures/generate.py` — stdlib-only Python, deterministic (seeded), fixtures
versioned and checked in. It plants the ground truth: fills, actions, the
amendment, and every twin's defect (duplicate, collision, leak, drift, withheld
price). It embeds the **naive fold** that emits custodian statements for P5.
The naive fold is **import-pinned**: a gate asserts it imports nothing from the
Go tree and reads only feed fixtures, so P5's independence claim is structural,
not asserted.

## 4. Gates and state of record

Each property = Go tests + a twin run. A single runner (`gates/run.sh`) asserts
every green cell passes and every twin cell fails with its exact planted count,
then emits the claimability table. **`STATUS.md` is the state of record from
commit one** — counts, lane status, claimability; README defers to it. CI runs
the full runner on every push.

**STATUS.md adopts BASELINE's CLAIMABLE semantics and row schema from day one**
(dated row, commit SHA, content hash, replay command), so later registration
into the BASELINE catalog is a copy, not a translation.

## 6. Scope walls (README before code)

- Synthetic fixtures only — the generator plants the truth; the ledger must
  recover it.
- No performance vocabulary; no benchmarks in v1. The speed claim is:
  replayable and byte-identical. Full stop.
- No floats anywhere.
- Named non-goals: lot selection (FIFO/specific-ID), FX/multi-currency, symbol
  changes, spin-offs, mergers, fractional shares.
- No market connectivity, live vendors, order management, execution. No
  production claim, stated on-page.
- The naive fold is import-pinned.
- CV/site silence until all six properties hold both cells.
- Lanes 2 (ClickHouse behind the Reader protocol) and 3 (Kafka transport,
  guarantees re-proven end-to-end) are promised by no one: empty cells on the
  claimability table, earned later or never.

## 7. Landing — amended from the seed's §6

The seed (08-27) decided "the ledger replaces BASELINE as the site's third
system." The BASELINE conformance-ledger build (08-31) invalidates the framing:
BASELINE is no longer a system competing for a slot — it is the **public claim
surface** systems register into. Amended landing:

- **DATUM** is the umbrella name for the family — the geodetic reference frame
  every point, angle, and line is defined against (and the singular of data).
  VANTAGE is a point, PARALLAX an angular displacement, BASELINE and MERIDIAN
  reference lines; DATUM is what they jointly constitute: a shared reference
  that makes independent measurements comparable and checkable. Producers
  measure (VANTAGE, MERIDIAN), the verifier re-derives (PARALLAX), the catalog
  records (BASELINE). New instruments join without renaming anything.
  (OBSERVATORY was considered and rejected: a metaphor you have to be told,
  not a description you can parse — it lacked intent-plane's clarity register.)
- Site trio stands as decided: policy (/intent), practice (/rigor),
  proof-in-domain (/ledger). The /ledger page follows the /baseline page
  template: thesis line, struts, failure taxonomy, claimability table.
- /baseline is **upstream infrastructure, not lineage**: MERIDIAN's six
  claimability cells land as BASELINE catalog rows once green+red. The lineage
  sentence (thesis #3, "the PIT discipline this ledger transplants was first
  proven on SEC fundamentals") still links back.
- CV: enters the Distributed Systems / Platform variants as the domain anchor;
  pairs with intent-plane. Displacement decisions per-variant, not global.
- Interview artifact: the two-minute recorded terminal session — clone, replay,
  hash-compare, run a twin, watch it go red.
